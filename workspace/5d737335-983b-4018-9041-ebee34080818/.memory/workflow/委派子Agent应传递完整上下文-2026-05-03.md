## 委派子Agent的工作流规范

### 问题记录

**本次问题**：委派 polisher subagent 时，只传递了提炼后的"修改要求"，而没有传递完整的 review 报告。

**后果**：如果对 review 结果的解读有偏差，子Agent也会跟着走偏。

---

### 正确做法

#### 1. 传递完整上下文

当需要先进行审查再修改时，工作流应该是：

```
用户: "review第X章"
    ↓
我: 调用 reviewer SubAgent 审查
    ↓
reviewer 返回完整报告
    ↓
我: 调用 chapter_polisher SubAgent 修改
    ↓
polisher task 中包含完整的 review 报告（作为 attachments 或直接写入 task）
```

**不要**：
- 自己读完文件后提炼问题
- 只把"修改清单"传给下一个 Agent
- 替 Agent 做理解和判断

**应该**：
- 把完整的审查报告（reviewer 的输出）原封不动地传给下一个 Agent
- 或者在 attachments 中附上报告文件

#### 2. 避免多余的读取操作

如果已经在 attachments 里提供了文件内容：
- 在 task 中明确写：`不需要再读文件，直接按以下要求修改`
- attachments 的 content 字段应该包含完整的文件内容

#### 3. 附件格式规范

```yaml
attachments:
  - path: "review_report.md"
    content: |
      ## 审阅报告
      （完整的 reviewer 输出内容）
  - path: "chapters/ch04.md"
    content: |
      （完整文件内容）
```

---

### 违反案例

**错误做法**（本次）：

```
1. 我自己读取文件
2. 写了详细的审阅报告
3. 提炼出"修改清单"写进 task
4. 只在 attachments 里放了大纲和章节内容
5. 子Agent 没有完整的 review 报告
```

**正确做法**：

```
1. 调用 reviewer SubAgent 审查
2. reviewer 返回完整报告，我保存到文件
3. 调用 chapter_polisher SubAgent
4. attachments 中附上完整的 review 报告文件
5. task 中写：参考附件中的审阅报告进行修改
```
